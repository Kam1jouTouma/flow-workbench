Flow 工作流使用说明

版本 0.16.1 · Windows 64 位 · 安装、示例流程与脚本开发

安装和启动

这是 Windows 64 位预览版 0.16.1。运行 FlowWorkbench-Setup-0.16.1.exe，选择目录并安装，无需管理员权限。默认安装到 %LOCALAPPDATA%\FlowWorkbench，桌面快捷方式可选。程序未签名，Windows 可能显示发布者未知；请确认文件来自发送者。也可以解压便携 ZIP，双击 launch.cmd。

运行环境

已包含 Java 21、Java 编译器、Python 3.12 和 Excel 合并依赖，无需另装 Java/Python。Java 编译示例支持目标 17/21，目标 25 需自行配置相应 JDK。文本、图片和现有 PDF 转换可直接运行；Word、Excel、PowerPoint 转 PDF 还需本机安装 Microsoft Office 或 LibreOffice。音频提取需勾选安装音频组件，或运行“安装音频组件.cmd”，联网从发布方下载约 100 MB 并验证哈希。

第一次使用

点击“打开”，从固定流程库选择示例，检查输入位置和输出目录后执行。示例数据会自动复制到数据文件夹；执行结果位于 outputs 下对应目录。示例默认复制并在重名时自动另取名称，不删除源文件。“导入”用于把外部流程加入自己的流程库。双击子图进入下一级画布，中键拖动画布，Shift 加滚轮缩放，右键节点打开菜单。

文件放在哪里

安装版默认数据目录为 %LOCALAPPDATA%\FlowWorkbench\data；便携版为程序目录下的 data。flow-library 存放流程图，samples 是测试材料，outputs 是执行结果，user-scripts 存放自己的脚本。双击“打开数据文件夹.cmd”即可找到。每个程序版本单独存放，重复安装不会覆盖旧程序；已有流程、脚本和样本不会被初始化覆盖。

预设计流程

01 单文件复制：一个输入到一个输出。
02 指定类型批量复制：文本、CSV、图片、PDF、Excel 文件批量复制。
03 文本图片逐文件 PDF：每个文件生成对应 PDF。
04 CSV 模板批量改名：模板 {姓名}_{x}，姓名匹配 CSV 表头。
05 双输入并行处理双输出：合并输入，分别改名和拼接 PDF，输出到两个目录。
06 子图封装复用：双击进入下一级画布。
07 Excel 合并：Python 处理多个工作簿。
08 Java 编译打包：批处理编译 Java 并生成 JAR。
09 音频提取：EXE 提取 MP3，需安装音频组件。

自己写脚本

data/user-scripts 已提供可运行模板。Python/copy_files.py 与 cli_v1.py 必须放在一起；修改 execute 函数可实现业务处理，prefix 参数可以给文件名添加前缀。BAT/copy_wrapper.bat 展示批处理如何调用同目录结构中的 Python 工具。Java/java-copy-demo.jar 可独立运行，src 包含源码；使用“重新编译.cmd”重新编译。EXE 可使用任何语言制作，只要遵循同一协议。通过“导入脚本”完成查询和协议校验后，现在可通过“导入脚本”添加为可执行FILE节点；需满足data/source端口规范。画布内置的工具可以正常执行。

命令行格式

查询：--help（说明）、--describe（工具与参数描述 JSON）、--capabilities（端口及格式能力 JSON）、--version（版本）。
执行：--input <绝对路径输入JSON> --config <绝对路径配置JSON> --output <绝对路径空目录>。
标准输出查询 JSON 使用 UTF-8；诊断写入标准错误。成功退出码为 0，模板执行错误为 4。工具只写暂存输出，不直接删除原文件或发布到用户最终目录。

输入和输出协议

input.json 包含 protocolVersion:1、runId、nodeId、inputs。inputs.data 为 FILE 端口，items 数组的 path 是输入文件绝对路径；inputs.source 为 JSON 端口，单个 item 指向来源清单。来源清单 files 与数据项对应，每项至少包含 originalPath、relativePath、sha256。config.json 包含 protocolVersion:1、parameters，例如 {"prefix":"copy_"}。
输出目录需要提前创建且为空。工具写入 payloads/ 文件、source.json 和 result.json。result.json 包含 protocolVersion、runId、nodeId、outputs，输出 items.path 必须是相对暂存目录的路径；source.json 保留原始来源和内容哈希。详细格式可直接参照随包独立模板与 cli_v1.py。

脚本运行示例

在 PowerShell 中，将下方的程序目录和数据目录替换成实际路径：
& "<程序目录>\runtime\python\python.exe" "<数据目录>\user-scripts\Python\copy_files.py" --help
& "<程序目录>\runtime\java\bin\java.exe" -jar "<数据目录>\user-scripts\Java\java-copy-demo.jar" --describe
& "<程序目录>\runtime\python\python.exe" "<数据目录>\user-scripts\Python\copy_files.py" --input "C:\test\input.json" --config "C:\test\config.json" --output "C:\test\empty-output"
手动运行 BAT 模板前设置 $env:FLOW_PYTHON="<程序目录>\runtime\python\python.exe"；手动重新编译 Java 模板前设置 $env:FLOW_APP_DIR="<程序目录>"。正常启动程序时这些变量自动设置。

朋友测试和反馈

先使用样本执行 01、03、04、05、07、08，再测试自己的文件副本。检查结果数量、内容、改名、再次运行的重名处理和子图进出。反馈请提供版本号、使用的流程、操作步骤、实际结果、预期结果和操作记录；使用匿名测试材料。通过Windows已安装应用或“卸载程序.cmd”移除程序；保留 data 目录可保留流程和脚本。第三方声明和来源见 licenses/DEPENDENCIES.txt。

系统设置、AI 与流程助手

顶部“设置”集中管理流程库、运行记录、并行任务数、Python 与 AI 服务。AI 服务填写完整 URL、model 和自己的 Key，Key 由 Windows DPAPI 保护。AI 节点可配置 prompt、输出 token 上限与超时。流程助手通过 MCP 建立草稿，检查后应用到画布，再手动执行。对话和草稿配置会发送给选定服务，可能包含路径；不会把 Key 作为工具结果返回。当前助手仅支持基础节点，不能生成子图；外部 stdio MCP 是独立草稿会话。

更多说明见 docs 文件夹。旧版本的个人设置不会随新版安装复制；在新版本重新配置服务，并通过系统设置选择已有流程库。

脚本开发和卸载

点击程序工具栏“导入脚本”，校验后直接加入画布。参数由侧边栏JSON对象配置；文件输入接脚本再接输出即可执行。脚本与依赖保留原位置。

打开从零开始的脚本适配教程

卸载：Windows设置“已安装的应用”中选择对应版本，或双击“卸载程序.cmd”。请先关闭程序；保留流程与用户数据，移除此版本AI配置。
