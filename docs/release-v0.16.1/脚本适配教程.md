# 脚本适配教程

适用于 **Flow 工作流 v0.16.1**。从随包模板开始，完成一次“文件输入 → 自定义脚本 → 文件输出”。

## 1. 第一次导入：先运行模板

1. 启动程序，双击“打开数据文件夹.cmd”，进入 `user-scripts/Python`。
2. 保持 `copy_files.py` 和 `cli_v1.py` 在同一目录。
3. 点击画布工具栏的“导入脚本”，选择 `copy_files.py`。校验通过后，程序将工具登记到脚本库，并添加“用户复制示例”节点。
4. 添加文件输入和文件输出，连接三个节点。输入选择“保留原文件”模式，设置源文件；输出设置目标目录。
5. 选中脚本节点，在侧边栏填写下面的参数，点击“检查”，再点击“执行”。

```json
{
  "prefix": "my_"
}
```

输入 `a.txt` 时，输出为 `my_a.txt`，原文件保留。

以后点击“导入脚本”或元素库中的“自定义脚本”，即可再次选用已登记的工具。

> 导入登记脚本原位置，不搬动文件。移动或修改入口脚本后，需要重新导入并使用新节点；已有节点会检查入口文件的哈希。

## 2. 文件放在哪里

建议每个工具使用一个文件夹，把入口脚本和依赖放在一起：

```text
data/
└── user-scripts/
    └── 我的工具/
        ├── copy_files.py
        └── cli_v1.py
```

- 安装包提供 Python、Java、BAT 三种可运行模板，位于 `data/user-scripts`。
- Python 解释器由系统设置选择，默认使用随包解释器。
- Java 模板包含源码及“重新编译.cmd”。
- 也可以导入其他目录的脚本，保持其依赖目录结构即可。
- 流程保存入口的绝对路径，不包含脚本文件本身。换电脑时需重新导入和配置。

### 当前支持范围

EXE、PY、BAT、CMD、JAR 使用同一协议。当前自定义节点要求输入和输出都包含以下两个端口：

- `data`：`FILE` 文件数据，按声明接收单个文件或文件集合。
- `source`：单项 `JSON` 来源清单。

当前不支持额外具名输入或 `TEXT` 直连。导入查询和执行都会运行脚本，请使用自己编写或可信的工具。

## 3. 命令行协议

### 查询接口

- `--help`：返回面向用户的帮助文字。
- `--describe`：返回单个 UTF-8 JSON，包含 `protocolVersion`、`id`、`name`、`version`、`description`、`inputs`、`outputs`、`parameters`。
- `--capabilities`：返回单个 JSON，包含 `capabilityVersion`、`toolId`、`toolVersion`、`implementation`、`operation`、`inputs`、`outputs`、`knownExtensions`。
- `--version`：返回版本号，必须与工具描述一致。

导入时程序实际调用以上四个接口；工具身份和版本必须相互一致。

### 执行接口

```text
--input <输入 JSON 的绝对路径>
--config <配置 JSON 的绝对路径>
--output <预先创建的空目录的绝对路径>
```

例如，使用 JAR 工具：

```powershell
java -jar my-tool.jar --input "C:\demo\input.json" --config "C:\demo\config.json" --output "C:\demo\stage"
```

- 成功退出码为 `0`；失败使用非零退出码，模板为 `4`。
- 标准输出留给查询结果，运行诊断写入标准错误。
- 不要在查询 JSON 中混入调试日志、广告或进度文字。
- 通用工具执行上限为 10 分钟；导入查询上限为 10 秒。内置 AI 节点使用自己的响应超时设置。

## 4. 数据如何传递

以下路径和哈希是示例占位值，手动运行时需替换。

### 输入请求：input.json

```json
{
  "protocolVersion": 1,
  "runId": "run-demo",
  "nodeId": "node-demo",
  "inputs": {
    "data": {
      "type": "FILE",
      "items": [{ "path": "C:/demo/a.txt" }]
    },
    "source": {
      "type": "JSON",
      "items": [{ "path": "C:/demo/source.json" }]
    }
  }
}
```

### 输入来源清单：source.json

```json
{
  "files": [
    {
      "originalPath": "C:/demo/a.txt",
      "relativePath": "a.txt",
      "sha256": "源文件内容的 SHA256"
    }
  ]
}
```

### 配置：config.json

```json
{
  "protocolVersion": 1,
  "parameters": {
    "prefix": "my_"
  }
}
```

### 暂存结果目录

工具只向 `--output` 指定的暂存目录写入结果：

```text
stage/
├── payloads/
│   └── my_a.txt
├── source.json
└── result.json
```

输出 `source.json` 应更新 `relativePath` 为结果名称、`sha256` 为结果内容哈希，同时保留原始来源信息。可参照模板里的 `originals` 字段，保存原文件路径与原始哈希。

### 结果清单：result.json

```json
{
  "protocolVersion": 1,
  "runId": "run-demo",
  "nodeId": "node-demo",
  "outputs": {
    "data": {
      "type": "FILE",
      "items": [{ "path": "payloads/my_a.txt" }]
    },
    "source": {
      "type": "JSON",
      "items": [{ "path": "source.json" }]
    }
  }
}
```

### 必须遵守的结果约定

- `runId` 和 `nodeId` 必须与输入一致。
- 输出路径必须相对于暂存目录，不能使用绝对路径、`../` 或指向目录外的路径。
- 结果文件与来源清单的 `files` 数量应一致。
- `relativePath` 是文件输出阶段使用的文件名；结果哈希应与实际内容一致。
- 保留原文件路径与原始哈希，供输出阶段判断保留或移动。

> 最终保存目录、重名处理和原文件删除由“文件输出”元素负责。脚本只处理暂存结果，不直接删除或覆盖用户文件。

## 5. 从 Python 模板改出自己的工具

复制整个 Python 模板目录，再编辑 `copy_files.py`：

1. 修改 `DESCRIPTION` 的 `id`、`name`、`version`、`description`。
2. 在 `DESCRIPTION.parameters` 声明配置项，填写 `name`、`type`、`default`、`required`。侧边栏参数的键和类型必须匹配声明。
3. 更新 `CAPABILITY` 的文件格式和单项／集合声明，与实际处理能力一致。
4. 在 `execute(request, parameters, output)` 编写业务处理。模板的 `inputs(request)` 读取并检查来源，`dump` 写 JSON，`sha` 计算哈希。
5. 保留 `cli_v1.py` 的命令行解析和身份检查，先验证查询接口，再导入程序执行样本。

例如，声明一个文件名前缀：

```python
{
    "name": "prefix",
    "label": "文件名前缀",
    "type": "string",
    "default": "copy_",
    "required": False
}
```

当前参数支持 `string`、`integer`、`number`、`boolean`，以及声明中的 `enum` 选项。

不要对 JSON 使用 `eval`，也不要将用户参数拼成 shell 命令；调用其他程序时使用参数数组。

## 6. BAT、JAR 和 EXE 怎么适配

### BAT / CMD

随包 BAT 模板展示如何调用相邻目录的 Python 工具。入口和依赖目录需一起保留，解释器通过 `FLOW_PYTHON` 指定。

### JAR

随包模板包含 Java 源码。使用 UTF-8 读写文件，以 `ProcessBuilder` 参数列表调用外部程序，并解析 `--input`、`--config`、`--output`。

```powershell
java -jar my-tool.jar --describe
```

返回符合规范的 JSON 即可，入口 `Main` 类不需要特殊语法。

### EXE

可用 C#、C++、Go 等语言编写，遵循相同的参数与 JSON 协议。EXE 本身不需要 Java。

C# 查询输出应使用 UTF-8：

```csharp
Console.OutputEncoding = new System.Text.UTF8Encoding(false);
```

如果包装其他进程，还应指定读取编码：

```csharp
start.StandardOutputEncoding = System.Text.Encoding.UTF8;
start.StandardErrorEncoding = System.Text.Encoding.UTF8;
```

否则中文描述可能被错误解码，导致 JSON 校验失败。

## 7. 常见问题

### 导入失败

检查依赖、Python 设置、描述字段、端口声明和四个查询接口。先与随包模板对照。

### 提示“脚本已修改”

重新导入新版，并添加新节点。旧节点保留原哈希，防止入口更改后直接执行。

### 参数格式错误

必须填写 JSON 对象，字符串使用双引号；参数键和类型应匹配描述，不能添加未声明的键。

### 结果无法发布

检查结果的运行／节点身份、相对路径、`source.files` 数量和哈希。

更完整的字段规范见 [工具规范 v1](../tool-protocol-v1/工具规范v1.md)。
