# 工作元素工具规范 v1

版本为 1.0，协议标识为 `protocolVersion: 1`，设计日期为 2026 年 10 月 13 日。规范用于 Java 工作流平台与独立 Python 脚本、Java 程序或可执行文件之间的通信，工作元素和输入输出适配器共用此接口。工具负责处理输入并产生输出，平台负责节点编排、配置界面、进程管理、日志和结果校验。

文中“必须”是接入要求，“可以”是可选能力。本规范规定接口，不表示执行引擎或工具已经实现。

## 1 工具包与启动方式

一个工具包包含程序、必要依赖和可选说明资源。功能描述由程序自身的 `--describe` 返回，不要求另写一份功能描述文件。平台提供 Python、Java JAR、Java 源文件和可执行程序四种导入方式，也允许用户配置自定义启动参数列表。

启动命令由平台本地登记，不能由工具返回的描述修改。登记内容至少包括可执行程序路径、固定参数列表和工具目录。Python 解释器、Java 运行时及依赖需要实际可用；统一协议不等于自动消除环境依赖。

| 形式 | 启动前缀示例 |
| --- | --- |
| Python | `python D:/tools/replace/replace.py` |
| Java JAR | `java -jar D:/tools/replace/replace.jar` |
| Java 源文件 | `java D:/tools/replace/ReplaceTool.java` |
| 可执行程序 | `D:/tools/replace/replace.exe` |

源码运行需要合适的 JDK。正式 Java 工具优先交付带入口及所需依赖的可执行 JAR；Python 工具需要声明解释器版本和依赖。资源文件相对于工具自身位置查找，不依赖进程当前工作目录。

平台使用可执行程序加参数列表直接启动，不把命令拼成 shell 字符串。手工在终端运行时，含空格的路径需要引号；参数列表中的路径值不额外嵌入引号。

## 2 命令行入口

| 模式 | 参数 | 输出与退出码 |
| --- | --- | --- |
| 人类帮助 | `--help` 或 `-h` | 标准输出为 UTF-8 帮助文字，成功退出 0 |
| 平台描述 | `--describe` | 标准输出为且仅为一个 UTF-8 JSON 对象，成功退出 0 |
| 工具版本 | `--version` | 标准输出为工具版本号及可选末尾换行，成功退出 0 |
| 执行 | `--input <文件> --config <文件> --output <目录>` | 处理数据，生成结果清单，成功退出 0 |

四种模式互斥。执行模式三个选项都必须提供，顺序不限，每个只能出现一次。v1 使用 `--name value`，不接收 `--name=value`、未知选项、额外位置参数或重复选项。无参数时输出帮助并退出 2。参数错误写标准错误并退出 2，不能静默忽略参数。

文件能力扩展 v1 新增可选查询模式 `--capabilities`，与上述模式互斥；返回独立能力对象，不改变原 `--describe` schema。规范见 `../file-capabilities-v1/文件类型与元素能力规范v1.md`。已实现的两个文件工具支持此扩展，平台通过它发现具体格式、数量和内容验证要求。

`--help`、`--describe`、`--version` 不读取任务输入、不创建结果、不调用模型或执行业务处理。描述必须在缺少业务凭据时仍可获取。三种查询模式不得在标准输出混入调试信息、进度或程序启动横幅。

帮助至少包含名称、用途、调用示例、三个执行参数、输入输出和环境依赖。`--version` 必须与描述中的 `version` 相同。

Python 示例：

```text
python replace.py --help
python replace.py --describe
python replace.py --input input.json --config config.json --output results
```

Java 示例：

```text
java -jar replace.jar --help
java -jar replace.jar --describe
java -jar replace.jar --input input.json --config config.json --output results
```

Java 工具使用 `main(String[] args)` 接收 JAR 文件名之后的这些参数。Python 可使用 `argparse`；两种语言最终遵循相同接口。Java 运行时选项放在 JAR 名之前，工具选项放在之后。

## 3 编码与基础结构

协议 JSON 使用 UTF-8，无 BOM，顶层必须是对象，禁止重复键、NaN、Infinity。标准日志也使用 UTF-8。工具输入和配置文件路径、输出目录路径由平台传入绝对路径。

JSON 对象成员顺序没有意义。描述中的端口和参数数组顺序用于界面显示；集合中的项目顺序有意义，工具不得未经声明重排。保留原始值，不能把缺失值、空字符串和空集合混为一谈。

所有协议文档包含整数 `protocolVersion: 1`。v1 对协议固定结构中的未知字段拒绝处理；用户参数和值文件内的业务 JSON 不受此规则直接限制。需要破坏接口或新增固定字段时发布新协议版本，不借用工具版本号改变协议含义。

工具 ID 使用小写字母开头，只含小写字母、数字、点、下划线和连字符，最长 100 个字符；例如 `text.replace`。端口和参数名称使用字母开头，只含字母、数字、下划线和连字符，最长 64 个字符，区分大小写。一个工具内输入端口名、输出端口名、参数名各自在所属列表中唯一。工具版本采用 `主版本.次版本.修订号`，例如 `1.0.0`。

## 4 工具描述

`--describe` 的必填字段是协议版本、工具 ID、显示名称、工具版本、用途、输入列表、输出列表和参数列表。没有对应项目时使用空数组。

```json
{
  "protocolVersion": 1,
  "id": "text.replace",
  "name": "文本替换",
  "version": "1.0.0",
  "description": "按字面匹配替换文本中的指定内容",
  "inputs": [{"name": "text", "label": "源文本", "types": ["TEXT"], "cardinality": "SINGLE", "required": true}],
  "outputs": [{"name": "text", "label": "替换结果", "types": ["TEXT"], "cardinality": "SINGLE", "required": true}],
  "parameters": [
    {"name": "find", "label": "查找内容", "type": "string", "required": true, "minLength": 1},
    {"name": "replace", "label": "替换内容", "type": "string", "required": false, "default": ""},
    {"name": "caseSensitive", "label": "区分大小写", "type": "boolean", "required": false, "default": true}
  ]
}
```

可以增加 `category`、`timeoutSeconds` 和 `requirements`。分类只是界面分组；输入、输出或工作元素类别由平台注册记录指定，不由 category 决定。工具建议超时默认 300 秒，必须是正整数，平台可以按用户配置覆盖。`requirements` 是文字列表，用于说明运行时、外部程序和业务凭据要求，不自动安装依赖。

### 4 1 端口描述

每个端口必须声明 `name`、`label`、`types`、`cardinality` 和 `required`。`description` 可选。`types` 为允许类型的非空去重列表。

| 类型 | 项目文件内容 |
| --- | --- |
| `TEXT` | UTF-8 无 BOM 文本，允许空内容 |
| `FILE` | 原始或生成文件，例如 Word、PDF、CSV、图片 |
| `JSON` | UTF-8 无 BOM 的合法 JSON 值，业务结构由工具说明约定 |

v1 不使用 `ANY` 作为实际类型。需要接受多种数据的端口列出明确类型。节点画布上的旧 `ANY` 占位在接入执行前需要转换为具体声明。

`SINGLE` 表示端口出现时恰好一个项目；`COLLECTION` 表示有序项目数组，默认允许空集合。集合端口可以声明 `minItems`、`maxItems`，两者为非负整数且前者不得大于后者，单项端口不得配置这两个字段。

`required` 表示端口不能缺失，不等同于内容非空。一个端口值的所有项目使用同一实际类型。不同端口可以有不同类型。工具不能把集合自动取第一项当作单项输入；逐项执行由平台明确组织或由工具声明集合能力。

### 4 2 参数描述

参数支持 `string`、`integer`、`number`、`boolean`。字符串可声明 `minLength`、`maxLength`，数字可声明包含端点的 `minimum`、`maximum`；范围上下界必须一致。整数按 JSON 数学值定义，不允许分数。`choices` 是同类型的非空去重候选值列表，可用于下拉框。`description`、`default` 可选。

可选 `widget` 值为 `text`、`textarea`、`select`、`file`、`directory`。字符串使用文本、多行或路径选择器；候选列表使用选择器；布尔和数字由类型生成默认控件。控件只是输入方式，不替代参数校验。`file`、`directory` 路径参数必须以绝对路径写入配置，路径是否必须存在由工具用途决定。

`default` 必须满足参数类型、范围和候选约束。平台先应用默认值，再检查必填值，把有效值写入配置；工具独立运行时也必须使用相同规则。未提供且没有默认值的可选参数可省略。必填指参数最终存在；字符串非空需另用 `minLength: 1`。v1 参数不接收 `null`，不自动把字符串 `"true"` 或 `"42"` 转换成布尔或数字。

## 5 输入文件

```json
{
  "protocolVersion": 1,
  "runId": "run-001",
  "nodeId": "node-replace",
  "inputs": {
    "text": {
      "type": "TEXT",
      "items": [{"path": "D:/jobs/run-001/source.txt", "mediaType": "text/plain"}]
    }
  }
}
```

`runId` 与 `nodeId` 是平台产生的非空身份字符串，工具必须在结果和错误清单中原样返回。`inputs` 的键必须对应描述中的输入端口名，未知端口、缺少必填端口、实际类型或数量不匹配均属于输入错误。

每个端口值包含 `type` 和 `items`。每项必须包含文件 `path`，`mediaType` 可选。TEXT 固定解释为 UTF-8 文本，JSON 固定解释为 UTF-8 JSON，FILE 保留原文件；未提供媒体类型时 FILE 按未知二进制处理，不通过扩展名自动承诺兼容性。

输入项目 `path` 必须是当前运行系统上的绝对文件路径。存在性、可读性和内容格式由平台与工具检查。工具将输入文件视为只读，不原地修改。输入不能是目录；目录扫描工具可以把目录作为配置参数，输出文件集合。复用同一文件的多个下游工具不应互相改变输入。

## 6 配置文件

```json
{
  "protocolVersion": 1,
  "parameters": {"find": "Python", "replace": "Java", "caseSensitive": true}
}
```

`parameters` 必须是对象，只允许描述中声明的参数名。没有参数也提供空对象。工具在业务处理前检查类型、必填、范围和候选值；配置结构或参数错误退出 2。不能忽略未知配置或自行补造业务事实。

业务配置统一进入 JSON，不给每个参数另扩展顶层命令行选项。这样工具保持少量固定选项，界面参数可按描述扩展，路径和多行文本不受命令行长度限制。

## 7 输出目录与结果清单

平台为每次节点调用准备独立、已存在且为空的输出目录，并以该目录作为执行工作目录。路径参数和输入路径仍使用绝对路径。工具可以在输出目录内创建子目录，所有正式结果必须放在这个目录内。

成功时必须生成 `result.json`：

```json
{
  "protocolVersion": 1,
  "runId": "run-001",
  "nodeId": "node-replace",
  "outputs": {
    "text": {
      "type": "TEXT",
      "items": [{"path": "replaced.txt", "mediaType": "text/plain"}]
    }
  }
}
```

输出项目 `path` 使用相对输出目录的路径，规范写法使用 `/`。禁止绝对路径、冒号与盘符、反斜杠、空路径、空路径段、`.` 或 `..` 路径段。平台解析真实路径后检查文件仍在输出目录内，包括符号链接目标；不得用越界引用充当正式结果。

结果端口名、实际类型和数量必须符合工具描述；未知端口、缺失必填输出、文件不存在或不可读、TEXT 编码错误、JSON 内容无法解析均导致调用失败。可选输出缺失时省略整个端口，不能用不合格的空单项代替。没有输出的工具仍生成 `outputs: {}`。

文件扩展名与 `mediaType` 只是描述，不能单独证明格式有效。PDF、Word 等具体内容检查由对应工具负责。相同工具的不同调用使用不同目录，不共享临时文件名。

工具先完成所有结果文件，再写完整清单，最后退出 0。清单应先写临时文件再更名，平台在进程退出后读取。仅产生文件不算成功。

**成功条件同时满足：退出码为 0、清单合法、身份一致、输出符合描述、结果文件可读。** v1 不接受部分成功；非零退出时，即使已产生部分文件，也不把它们交给下游。输出目录保留供诊断。

## 8 日志与失败

执行模式的标准输出用于普通日志，标准错误用于警告或错误，两者均为 UTF-8 文本。平台分别采集，并加上运行、节点及时间信息；读取两个通道必须并行进行，避免缓冲区阻塞。v1 不从日志文字推断成功，不规定机器可读进度事件。

| 退出码 | 含义 |
| --- | --- |
| 0 | 工具声明处理成功，平台还需检查结果 |
| 1 | 业务处理或未分类运行失败 |
| 2 | 命令行、协议版本、输入清单结构或配置参数错误 |
| 3 | 运行依赖或业务凭据未满足 |
| 4 | 输入文件不可读取、内容损坏或业务内容不符合要求 |

未列出的非零退出码统一视为失败。成功过程中可以有标准错误警告，不能仅因 stderr 非空认定失败。

能取得运行身份时，失败可以额外生成 `error.json`：

```json
{
  "protocolVersion": 1,
  "runId": "run-001",
  "nodeId": "node-replace",
  "error": {"code": "INPUT_UNREADABLE", "message": "无法读取源文本", "port": "text", "itemIndex": 0}
}
```

`code` 是稳定的机器错误标识，以大写字母开头，只使用大写字母、数字和下划线；`message` 是人类可读说明。`port`、从 0 开始的 `itemIndex`、`details` 对象可选。错误清单不替代退出码；非法错误清单只作为附加诊断，不能掩盖原失败。尚未读到身份的参数错误只输出标准错误即可。

平台主动取消、超时、无法启动、结果校验失败使用平台状态记录，不能伪装成工具返回的退出码。取消或超时停止该调用及其子进程，并等到停止后再终结运行状态。v1 不支持恢复或继续消费部分输出。

## 9 平台接入顺序

1. 用户选择程序类型及文件，平台登记实际启动前缀。
2. 调用 `--describe`，建议查询超时 10 秒；解析 JSON、检查版本及描述约束。
3. 将描述缓存成工具版本快照，生成元素、端口和参数界面。
4. 校验流程绑定，生成绝对输入路径、有效参数和独立输出目录。
5. 启动执行模式，并行收集 stdout、stderr；按用户配置控制超时和取消。
6. 等待退出，检查 `result.json`，解析成平台内部数据，再交给下游。

同一工具 ID 的版本可并存，节点绑定明确版本和启动登记。同一 ID 与版本的重复导入提示用户处理，不静默替换。运行保存本次使用的描述和配置快照；工具更新后重新查询，已有流程发现端口或参数变化时提示重新确认。此处快照用于追踪，不等于自动保留完整运行环境。

默认查询超时 10 秒、执行超时 300 秒是平台初始设置，用户可覆盖。大日志采用流式读取和落盘，不无限堆积内存；查询 JSON 的默认读取上限可设为 1 MiB，超限提示用户，不静默截断后解析。

## 10 v1 实现范围

v1 包含工具自描述、基础参数表单、具名多端口、单项与集合、基于文件的数据传递、外部进程执行、成功结果和失败诊断。JSON 能承载结构化业务数据，但两端仍需约定字段语义；仅类型同为 JSON 不证明含义兼容。

暂不规定跨工具通用表格结构、JSON Schema 业务结构发现、任意脚本自动安装、条件循环、流式数据、部分成功、进度事件、子图执行或网络服务协议。后续能力应依据实际场景增补，不把这些内容当作当前已实现能力。

新工具模板应封装参数解析、帮助描述输出、JSON 读取、约束检查、结果清单及错误处理。工具作者主要维护元数据和一个处理函数，不需要理解画布、节点调度或历史存储。

## 11 接入验收

| 检查 | 通过条件 |
| --- | --- |
| 查询 | help、describe、version 独立工作，描述 stdout 可直接解析 |
| 命令行 | 参数乱序可用，缺失、未知、重复和混合模式明确拒绝 |
| 描述 | 名称唯一，默认值和约束一致，端口数量规则有效 |
| 输入 | 中文与空格路径、空文本、缺文件、错误类型和数量行为明确 |
| 配置 | 布尔数字不靠字符串转换，未知参数拒绝，默认值统一 |
| 输出 | 路径位于输出目录，文件存在，清单身份和端口一致 |
| 失败 | 非零退出阻止下游，日志保留，不能把部分文件当成功 |
| 多次调用 | 调用目录独立，输入未被修改，输出不会串值 |
| 环境 | 平台能报告无法启动；工具能报告缺少业务依赖或凭据，缺少业务凭据时描述仍可查询 |

`schemas/` 提供描述、输入、配置、结果和错误清单的结构定义；`examples/` 提供文本替换的完整数据样例。结构校验还必须结合本规范中的跨字段、文件系统、端口声明及参数规则，不能只检查 JSON Schema 就认定运行成功。
